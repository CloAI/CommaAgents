# Run Systems

Run systems provide the capabilities that surround strategy execution. Each module owns one concern for the lifetime of a prepared run and releases its resources when that run finishes, fails, is cancelled, or is discarded.

| Module | Responsibility | Client-facing surface |
|---|---|---|
| [Input](/docs/daemon/run-system/systems/input) | User-agent input collection | `request_input`, `user_input` |
| [Permission](/docs/daemon/run-system/systems/permission) | Interactive operation approval | `request_permission`, `permission_decision`, `update_policy` |
| [Question](/docs/daemon/run-system/systems/question) | Structured user questions | `request_question`, `question_response` |
| [Steering](/docs/daemon/run-system/systems/steering) | Messages queued for a live run | `steer_run`, `steer_queued` |
| [Sandbox](/docs/daemon/run-system/systems/sandbox) | Run-scoped filesystem and command boundaries | Permission requests |
| [Skills](/docs/daemon/run-system/systems/skills) | Workspace and global skill discovery | Agent skill tools |
| [MCP](/docs/daemon/run-system/systems/mcp) | MCP connections and agent tool assignment | MCP status during preparation |
| [Streaming](/docs/daemon/run-system/systems/streaming) | Agent and step events | Observation events |
| [Persistence](/docs/daemon/run-system/systems/persistence) | Run timeline recording | Run listing and continuation |
| [Sub-launch](/docs/daemon/run-system/systems/sub-launch) | Nested strategy execution | Spawned strategy results |

These modules are composed by `createRunSystem`; applications do not need to construct them individually.
