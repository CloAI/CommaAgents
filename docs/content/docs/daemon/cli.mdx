# CLI

The primary daemon management interface is `comma daemon`. The package also provides the standalone `comma-agents-daemon` binary for direct process control.

```bash
comma daemon start
comma daemon status
comma daemon stop
comma daemon restart
comma daemon logs
```

Use `comma daemon enable` or `comma daemon disable` to manage user-level daemon autostart.

The standalone binary supports `start`, `stop`, `restart`, `status`, and `logs`. Autostart commands are only available through `comma daemon`.

## start

Starts the daemon. By default, it detaches and runs in the background. Pass `--foreground` to run in the current terminal.

```bash
# Background mode (default)
comma-agents-daemon start

# Foreground mode
comma-agents-daemon start --foreground
```

**Flags**

| Option | Alias | Type | Default | Description |
|---|---|---|---|---|
| `--foreground` | `-f` | boolean | `false` | Run in the foreground (don't daemonize) |
| `--port` | `-p` | number | from config | Override the listening port |
| `--verbose` | `-v` | boolean | `false` | Enable debug-level logging |

```bash
# Start on a custom port
comma-agents-daemon start --port 9090

# Start in foreground with verbose logging
comma-agents-daemon start --foreground --verbose
```

The CLI starts the plugin kernel and exposes its commands and channels over the [plugin server](/docs/daemon/server/plugin-server) WebSocket at `/ws`. Background startup waits for the launched daemon to publish its PID after the listener starts and verifies that process is still running. Configuration flags, environment variables, and configuration-file precedence remain the same.

For repository debugging, run the shared foreground runtime with:

```bash
bun run scripts/debug-daemon.ts
```

Both entry points write the configured PID file and release it on shutdown.

If the daemon is already running, `start` exits with an error message and exit code 1.

## restart

Stops the daemon, then starts it again with the same flags as `start`.

```bash
comma daemon restart
comma-agents-daemon restart --verbose
```

## stop

Stops a running daemon by sending SIGTERM to the process recorded in the PID file. It polls for up to 5 seconds for the process to exit.

```bash
# Stop the daemon
comma-agents-daemon stop
```

If no PID file is found (or it's stale), the command exits cleanly with status code 0.

## status

Reports whether the daemon is running, and if so, prints configuration details.

```bash
# Check daemon status
comma-agents-daemon status
comma daemon status --json
```

**Sample output (running)**

```
Daemon is running (PID: 12345)
  Config: /home/user/.comma/daemon.json
  PID file: /home/user/.comma/daemon.pid
  Port: 7422
  Host: 127.0.0.1
```

**Sample output (not running)**

```
Daemon is not running
```

## autostart

Autostart is managed through `comma daemon enable` and `comma daemon disable`.

| Platform | Mechanism |
|---|---|
| macOS | launchd user agent |
| Linux | systemd user service |
| Windows | user logon scheduled task |

## logs

Print the configured daemon log-file path:

```bash
comma daemon logs
```

When no file sink is configured, the command reports that no daemon log file is available. Foreground and service-manager logs may still be available through standard error or the platform service log.
