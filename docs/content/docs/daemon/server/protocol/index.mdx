The daemon communicates with clients over a WebSocket connection at `/ws`. All messages are JSON objects validated against the protocol schemas. Each message has a `type` field that identifies its kind.

## Connection Lifecycle

1. Client opens a WebSocket to `ws://host:port/ws`.
2. The daemon assigns a `clientId` and tracks the connection.
3. Client sends JSON messages (requests). Daemon replies with JSON messages (responses/events).
4. On disconnect, the daemon removes the client from all subscriptions.

A health check is available at `GET /health`, returning `{ status, uptime, activeRuns, connectedClients }`.

## Message Envelopes

Every message extends a base envelope.

### Client Messages

All client-to-daemon messages include an optional `requestId`. When provided, the daemon echoes it back on the response so the client can correlate request/response pairs.

```json
{
  "type": "ping",
  "requestId": "abc-123"
}
```

### Daemon Messages

All daemon-to-client messages include a `ts` field (ISO-8601 timestamp) and an optional `requestId` echoed from the triggering request.

```json
{
  "type": "pong",
  "requestId": "abc-123",
  "ts": "2025-01-15T10:30:00.000Z"
}
```

## TypeScript parsing

Use the package parsers before handling messages received from an untyped transport or fixture.

```ts
import { parseClientMessage, parseDaemonMessage } from "@comma-agents/daemon";

const clientPayload = '{"type":"ping","requestId":"ping-1"}';
const daemonPayload = '{"type":"pong","requestId":"ping-1","ts":"2026-07-04T12:00:00.000Z"}';

const clientResult = parseClientMessage(JSON.parse(clientPayload));
if (clientResult.success) {
  console.log(clientResult.data.type);
}

const daemonResult = parseDaemonMessage(JSON.parse(daemonPayload));
if (!daemonResult.success) {
  console.error(daemonResult.error.message);
}
```

Successful results contain a typed `ClientMessage` or `DaemonMessage` in `data`. Failed results contain validation details in `error`.

## Error Handling

The daemon sends an `error` message for protocol-level failures. Every error includes a machine-readable `code` and a human-readable `message`:

```json
{
  "type": "error",
  "code": "VALIDATION_ERROR",
  "message": "Missing required field: strategyPath",
  "ts": "2025-01-15T10:30:00.000Z"
}
```

### Error Codes

| Code | When |
|---|---|
| `PARSE_ERROR` | Invalid JSON received on the WebSocket |
| `VALIDATION_ERROR` | JSON is valid but fails schema validation |
| `INTERNAL_ERROR` | An unexpected daemon operation failed |
| `NO_PENDING_INPUT` | `user_input` sent but no agent is waiting for input |
| `NO_PENDING_PERMISSION` | `permission_decision` does not match a pending request |
| `NO_PENDING_QUESTION` | `question_response` does not match a pending request |
| `SUBSCRIBE_ERROR` | `subscribe` failed (run not found or client not registered) |
| `EXECUTION_ERROR` | Strategy file not found, parse error, or model resolution failure |
| `PREPARE_FAILED` | Strategy or run systems could not be prepared |
| `START_FAILED` | The requested run is unknown or was already started |
| `CANCELLED` | Run was explicitly stopped via `stop_run` |
| `RUN_NOT_STEERABLE` | `steer_run` sent for a run that is not found or has already finished |
| `RESTORE_FAILED` | A trash entry could not be restored |
| `HUB_ERROR` | A Hub list, install, update, or remove operation failed |
