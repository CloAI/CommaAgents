Skills are directories of reusable instructions and supporting files. Agents search names and descriptions, decide which skill applies, and load its full instructions on demand. Searching does not select a skill or add its body to the prompt.

## Create a skill

Save this as `~/.config/comma/skills/code-review/SKILL.md` or `<project>/.comma/skills/code-review/SKILL.md`:

```md
---
name: code-review
description: >
  Review code changes for correctness, maintainability,
  and missing validation.
metadata:
  owner: engineering
---

# Code review

Read the changed code and its callers. Explain concrete defects and the
validation needed to establish that they are fixed.
```

Both `SKILL.md` and `SKILL.MD` are accepted. If both exist in one directory, `SKILL.md` wins and discovery reports a warning. The YAML frontmatter must be a mapping with a nonempty `name` and `description`. Names contain lowercase letters, digits, and hyphens, start with a letter or digit, and are at most 64 characters. Other valid frontmatter fields are ignored and have no runtime effect. The Markdown body is returned as instructions without its frontmatter.

Each file is limited to 256 KiB. Supporting files can sit beside it; their contents are not loaded automatically.

## Discovery and merging

Every source contributes skills to one collection. Only duplicate names use precedence, highest first:

1. The nearest Comma project's `.comma/skills`.
2. Explicit additional directories, with later entries winning conflicts.
3. `~/.config/comma/skills`.
4. `~/.comma/skills`, retained for compatibility.
5. `~/.agents/skills`.

Comma finds the project by walking upward from the supplied workspace for a `.comma` directory. Git metadata is not used. The global Comma data directory is not treated as a project marker. A project is optional: global and configured sources remain available when none is found, and discovery does not create `.comma`. The daemon logs a missing-project warning without sending a client error or notification.

Each root is scanned only for direct child skill directories. Linked directories may point outside the root, and aliases of the same source are deduplicated. Nested groups are not scanned recursively. There is no automatic discovery from `.claude`, `.codex`, or OpenCode locations.

Malformed files, unreadable sources, broken links, duplicate filenames, and shadowed names produce diagnostics while valid skills remain usable. Within one source, directories are considered in name order, making duplicate-name selection deterministic. Missing optional discovery directories are allowed.

## Use core directly

```ts
import { loadSkills, searchSkills } from "@comma-agents/core/skills";

const { registry, warnings, projectRoot } = await loadSkills(process.cwd(), {
  additionalDirectories: ["~/team-skills", "./shared-skills"],
});

const candidates = searchSkills(registry, {
  query: "code reveiw",
  limit: 10,
});

for (const candidate of candidates.matches) {
  console.log(candidate.name, candidate.description, candidate.score);
}

const instructions = registry.get("code-review");
```

Search is case-insensitive and typo-tolerant. Names have greater ranking weight than descriptions. Lower scores indicate closer matches; ties use skill-name order. The result includes metadata and `totalMatches` before limiting, without instruction bodies. The default limit is 10, and accepted limits are integers from 1 through 50. A nonempty query with no matches returns an empty result.

Absolute paths and `~/` paths are supported. Relative additional paths resolve against the supplied workspace. An explicit `globalSkillsDir` replaces the conventional global sources; `null` disables them. `projectSkillsDir` similarly overrides or disables project discovery. Additional directories remain explicit global-scope sources, with their source paths retained in results.

## Agent tools and execution snapshots

Built-in tools are available by default, including [`search_skills`](/docs/core/tools/built-in/skill-tools/search_skills), [`list_skills`](/docs/core/tools/built-in/skill-tools/list_skills), and [`load_skill`](/docs/core/tools/built-in/skill-tools/load_skill). An explicit agent `tools` list restricts built-ins; `tools: []` disables them. MCP server selection remains separate.

The strategy loader provides concise guidance for the skill tools actually available. It does not insert the entire skill index into every initial prompt. To require instructions for a strategy agent, use its `skills` field:

```yaml
agents:
  reviewer:
    model: openai/gpt-4o
    tools: [search_skills, load_skill, read_file]
    skills: [code-review]
```

Required skills are inserted in full. An unresolved required name prevents strategy loading. Other skills remain candidates for the model to discover and load.

The daemon captures skills during each run preparation. Root and child executions have separate registries; continuations rediscover files. Active snapshots do not change when files are edited. Completion, cancellation, failed preparation, and disposal release the snapshot. Historical skill snapshots are not persisted.

See [Skills plugin](/docs/daemon/skills-plugin) for workspace and active-run inspection through the daemon.
