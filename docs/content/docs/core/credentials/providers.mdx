# Supported providers

Comma-agents ships with well-known environment variable mappings for common AI providers. When a credential is needed, the store checks these variables automatically — no configuration required.

## Provider table

| Provider ID      | Environment variable(s)                          | Notes                                                |
| ---------------- | ------------------------------------------------ | ---------------------------------------------------- |
| `openai`         | `OPENAI_API_KEY`                                 |                                                      |
| `anthropic`      | `ANTHROPIC_API_KEY`                              |                                                      |
| `google`         | `GOOGLE_GENERATIVE_AI_API_KEY`, `GOOGLE_API_KEY` | First match wins                                     |
| `google-vertex`  | `GOOGLE_VERTEX_API_KEY`                          |                                                      |
| `github-copilot` | `GITHUB_TOKEN`                                   | Uses OpenAI-compatible endpoint with Copilot headers |
| `mistral`        | `MISTRAL_API_KEY`                                |                                                      |
| `cohere`         | `COHERE_API_KEY`                                 |                                                      |
| `groq`           | `GROQ_API_KEY`                                   |                                                      |
| `perplexity`     | `PERPLEXITY_API_KEY`                             |                                                      |
| `fireworks`      | `FIREWORKS_API_KEY`                              |                                                      |
| `together`       | `TOGETHER_AI_API_KEY`, `TOGETHER_API_KEY`        | First match wins                                     |
| `deepseek`       | `DEEPSEEK_API_KEY`                               |                                                      |
| `xai`            | `XAI_API_KEY`                                    |                                                      |
| `openrouter`     | `OPENROUTER_API_KEY`                             |                                                      |

For providers with multiple env var aliases (e.g. `google`, `together`), the first variable listed is checked first. The second is a fallback alias.

## Providers without built-in env vars

Some providers work out of the box without API keys or use alternative authentication:

| Provider ID | Authentication                                                |
| ----------- | ------------------------------------------------------------- |
| `ollama`    | No key needed (local inference)                               |
| `bedrock`   | AWS credentials (IAM role, `AWS_ACCESS_KEY_ID`, etc.)         |
| `azure`     | Azure-specific auth (managed identity, `AZURE_API_KEY`, etc.) |

These providers can be registered via `registerProviderDefinition()` and their credentials managed through the credential store's `custom` credential type or by setting environment variables directly.

## Custom env var mappings

If a provider uses a non-standard env var name, pass `envVarOverrides` when creating the credential store:

```ts
import {
  createCredentialStore,
  createJsonFileCredentialBackend,
  getCredentialsPath,
} from "@comma-agents/core";

const store = createCredentialStore({
  backend: createJsonFileCredentialBackend({ filePath: getCredentialsPath() }),
  envVarOverrides: {
    // Override the default env var for OpenAI
    openai: ["MY_CUSTOM_OPENAI_KEY"],
    // Add a new provider not in the built-in list
    "my-provider": ["MY_PROVIDER_API_KEY"],
  },
});
```

Overrides replace (not merge with) the built-in entry for a given provider ID. Providers not mentioned in `envVarOverrides` keep their default env var mappings.

## Declarative provider settings

Use core's provider settings APIs from any project, with or without the daemon. Custom endpoint definitions and manually added models persist in `~/.comma/provider-settings.json`, separately from credentials and the downloaded public catalog. The application data directory and provider-settings path can be overridden through core's defaults API.

```json
{
  "version": 3,
  "providers": [
    {
      "kind": "custom",
      "id": "local",
      "definition": {
        "name": "Local Server",
        "baseURL": "http://localhost:1234/v1",
        "credentialType": "none"
      },
      "models": [
        {
          "id": "org/my-model",
          "metadata": {
            "name": "My Model",
            "contextWindow": 32768
          }
        }
      ]
    },
    {
      "kind": "existing",
      "id": "openai",
      "models": [
        {
          "id": "my-deployment"
        }
      ]
    }
  ]
}
```

A custom endpoint includes its name, complete API prefix, authentication mode, and manual models. An existing provider uses `kind: "existing"`, its `id`, and a `models` array. Custom endpoints use `kind: "custom"` and keep connection fields in `definition`. Each manual model has an `id` and optional nested `metadata`. This adds models without copying or overriding the provider definition. Custom endpoint IDs must be unique and cannot replace catalog, built-in, or independently registered providers. IDs remain unchanged when an endpoint is updated.

Only version 3 settings are accepted. Previous versions and string model entries are rejected; files are never migrated or rewritten on read.

Create a local endpoint and use a provider-qualified model ID:

```ts
import {
  addCustomProvider,
  addCustomProviderModel,
  resolveModel,
} from "@comma-agents/core";

await addCustomProvider({
  id: "local",
  name: "Local Server",
  baseURL: "http://localhost:1234/v1",
  credentialType: "none",
  models: [{ id: "org/my-model", metadata: { name: "My Model", contextWindow: 32768 } }],
});

await addCustomProviderModel({
  providerId: "openai",
  modelId: "my-deployment",
  metadata: {
    name: "My Deployment",
    capabilities: { tools: true, vision: false },
    cost: { input: 0.5, output: 1.5 },
  },
});

const model = await resolveModel("local/org/my-model");
```

Use `credentialType: "api"` when the endpoint requires a key. HTTP and HTTPS prefixes are accepted; embedded URL credentials, query strings, and fragments are rejected. Include `/v1` yourself when needed. No request is made when an endpoint or manual model is added.

Manual models are additive and survive live discovery. Their metadata fills only fields missing from catalog or live results, including individual capability, modality, and pricing fields. Known values such as `false`, zero prices, and empty modality lists remain unchanged. Manual-only models have `sources: ["user"]`; omitted capabilities remain unknown. User-owned provider definitions have `origin: "user"`. Bare-model automatic provider selection remains catalog-based, so select manually added models with `provider/model`.

`addCustomProviderModel` accepts optional `metadata` separately from `modelId`. Token limits must be nonnegative integers and prices must be nonnegative numbers. Repeating an existing manual ID is a no-op, including when different metadata is supplied. `addCustomProvider` accepts model objects with an `id` and optional nested `metadata`; string entries are unsupported.

## Editing user configuration

`updateCustomProvider` changes a persisted endpoint's name, API prefix, or authentication mode. `removeCustomProviderModel` removes only a manual entry; it does not hide a model returned by catalog or live discovery.

```ts
import {
  updateCustomProvider,
  removeCustomProviderModel,
  removeCustomProvider,
} from "@comma-agents/core";

await updateCustomProvider({ providerId: "local", name: "Development Server" });
await removeCustomProviderModel({
  providerId: "local",
  modelId: "org/my-model",
});
const removal = await removeCustomProvider({ providerId: "local" });
console.log(removal.removed);
```

Additions, updates, and model mutations return the updated provider metadata without live discovery or verification. Repeated model additions/removals are idempotent. Removing the last manual model for an existing provider removes its settings-only entry; a custom endpoint can remain with an empty model list.

Removing a custom endpoint removes its global credential before its definition and manual models. If the settings removal fails after the key was removed, the operation reports `PROVIDER_REMOVAL_PARTIAL`; retry removal. Strategy-scoped and environment credentials remain unchanged. Existing runs and model instances retain their configuration. These settings operations cannot remove independently owned provider definitions.

## Provider configuration and verification

Use `getProviderConfiguration` to read credential availability, the effective credential source, verification support, editable custom endpoint fields, and saved manual model objects without reading secret values. `configureProvider` saves or replaces a global API key. `removeProviderCredential` removes only the global key and returns the remaining configuration.

```ts
import {
  configureProvider,
  getProviderConfiguration,
  verifyProvider,
  removeProviderCredential,
} from "@comma-agents/core";

await configureProvider({ providerId: "openai", apiKey: "your-api-key" });
const configuration = await getProviderConfiguration({ providerId: "openai" });
console.log(configuration.credentialSource);
for (const model of configuration.customModels) {
  console.log(model.id, model.name, model.capabilities);
}

const verification = await verifyProvider({ providerId: "openai" });
console.log(verification.status);

await removeProviderCredential({ providerId: "openai" });
```

Environment credentials take precedence over saved global keys. `authStatus: "configured"` reports availability, not verified access. Custom endpoints with `credentialType: "none"` can resolve models without credentials.

Verification makes one authenticated model-list request for OpenAI, Anthropic, or Gemini. It never generates text or consumes generation tokens, makes no retries, rejects redirects, and has a five-second timeout. Other providers return `unsupported`. Its result contains `providerId`, a typed `status`, and an ISO `checkedAt` timestamp. It is not persisted and does not establish generation permissions or credit.

## Discovery and reload

OpenAI, Anthropic, and Google support live discovery with API keys. Anthropic and Google discovery follow all result pages. Google lists models supporting `generateContent` and returns IDs without the `models/` prefix. Available names and token limits enrich catalog metadata; missing pricing and capabilities come from matching catalog entries. OpenAI subscription credentials continue to use subscription model discovery.

Venice supports live model discovery with an API key (`VENICE_API_KEY`). Results include available text models, context windows, capability flags, and USD token pricing. Offline models and non-text models are excluded.

Venice's `supportsTeeAttestation` and `supportsE2EE` flags appear as `capabilities.teeAttestation` and `capabilities.e2ee`. Provider settings show badges and filters for **TEE attestation support** and **E2EE support**. These describe what the model supports; they do not indicate a verified enclave or an encrypted request. Encrypted inference requires attestation verification, client-side message encryption, and response decryption as described in [Venice's TEE and E2EE guide](https://docs.venice.ai/guides/features/tee-e2ee-models).

Catalog-only discovery is the default. Pass `live: true` to query existing provider-specific listers. Live model results have no TTL or result cache, and no background refresh runs. A failed or empty live result falls back to catalog data with nested `discovery.status` metadata; the result includes the union of provider, models.dev, and manual IDs. Metadata merges per field with priority provider, then models.dev, then manual, including individual capability, modality, and pricing fields. Arrays are complete values. Model results contain `id`, `sources`, and nested `metadata`; discovery timestamps and safe errors belong to `discovery`.

```ts
import {
  getGlobalCredentialStore,
  listProviders,
  reloadProviderSettings,
} from "@comma-agents/core";

const providers = await listProviders(getGlobalCredentialStore(), {
  live: true,
});
await reloadProviderSettings();
```

Settings load lazily. API writes take effect immediately; external edits require an explicit reload or process restart. Invalid or unreadable settings fail clearly and are not overwritten. Reload failure preserves the last valid runtime configuration. Settings and credential mutations are serialized within their owning store; this does not provide cross-process locking.
