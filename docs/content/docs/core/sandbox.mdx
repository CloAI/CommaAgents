# Sandbox

A sandbox provides the access policy used by an agent's tools. It resolves paths, checks workspace boundaries, evaluates tool policies, and requests permission when a policy returns `"ask"`.

The sandbox controls tools that use `ToolContext.guard`; it is not operating-system or process isolation.

```ts
import { createAgent } from "@comma-agents/core";
import { createSandbox } from "@comma-agents/core/sandbox";

const sandbox = createSandbox(
  {
    cwd: "/projects/my-app",
    outsideWorkspace: "deny",
    absolutePaths: "deny",
    write: { default: "ask" },
  },
  {
    onAsk: async ({ operation, resource }) => {
      const answer = globalThis.prompt(
        `Allow ${operation} on ${resource}? [y/N]`,
      );
      return answer?.toLowerCase() === "y" ? "allow" : "deny";
    },
  },
);

const agent = createAgent(
  {
    name: "workspace-editor",
    model: "openai/gpt-4o",
    tools: ["read_file", "edit_file", "run_command"],
  },
  { sandbox },
);
```

When no sandbox is supplied, directly created agents use a permissive sandbox rooted at `process.cwd()`.

## Strategy-wide sandbox

Pass the sandbox when loading a strategy. Every agent and nested strategy receives the same sandbox and policy updates.

```ts
import { loadStrategy } from "@comma-agents/core";
import { createSandbox } from "@comma-agents/core/sandbox";

const sandbox = createSandbox({
  cwd: process.cwd(),
  outsideWorkspace: "deny",
  forbiddenGlobs: [".git/**", "**/.env*", "**/*.key"],
});

const strategy = await loadStrategy("./strategy.yaml", { sandbox });
const result = await strategy.flow.call("Review the repository");
```

## Predefined options

Use the predefined option objects when you want an explicit standard profile.

```ts
import {
  createSandbox,
  DEFAULT_SANDBOX_OPTIONS,
  PERMISSIVE_SANDBOX_OPTIONS,
} from "@comma-agents/core/sandbox";

const workspaceSandbox = createSandbox(DEFAULT_SANDBOX_OPTIONS);
const unrestrictedSandbox = createSandbox(PERMISSIVE_SANDBOX_OPTIONS);
```

`DEFAULT_SANDBOX_OPTIONS` rejects absolute and outside-workspace paths, blocks common secret files, and allows reads and writes within the workspace. `PERMISSIVE_SANDBOX_OPTIONS` allows absolute and outside-workspace paths and applies no forbidden globs.

## PathPolicy

A read or write policy evaluates deny patterns, then allow patterns, then its default decision.

<AutoTypeTable path="../packages/core/src/sandbox/sandbox.types.ts" name="PathPolicy" />

```ts
const sandbox = createSandbox({
  cwd: process.cwd(),
  read: {
    default: "ask",
    allow: ["src/**", "package.json"],
    deny: ["src/secrets/**"],
  },
});
```

Patterns are relative to `cwd`. Deny patterns take precedence over allow patterns.

## Workspace boundaries

`outsideWorkspace` controls resolved paths outside `cwd`, including paths that escape through symlinks. Set it to `"deny"`, `"ask"`, or `"allow"`.

```ts
const sandbox = createSandbox({
  cwd: "/projects/app",
  outsideWorkspace: "ask",
  absolutePaths: "allow",
});
```

`absolutePaths` controls whether a tool may submit an absolute path. It does not determine whether that path is inside the workspace; `outsideWorkspace` handles that decision after resolution.

## Guard

Every tool receives a guard through `ToolContext.guard`.

```ts
const absolutePath = await toolContext.guard.authorize(
  { type: "fs.read", resource: "src/index.ts" },
  {
    agentName: toolContext.agentName,
    toolName: "read_file",
    signal: toolContext.abort,
  },

```

Use `canAccess()` when filtering search or directory results without presenting permission prompts.

## Policy

Policies return `"allow"`, `"deny"`, `"ask"`, or `"pass"`. The priority layer determines evaluation order: mandatory restrictions, session decisions, tool policies, then default path policies.

<AutoTypeTable path="../packages/core/src/guard/guard.types.ts" name="Policy" />

<AutoTypeTable path="../packages/core/src/guard/guard.types.ts" name="PolicyPriority" />

```ts
import {
  approveCommandsPolicy,
  denyCommandsPolicy,
} from "@comma-agents/core/sandbox";

const policies = [
  denyCommandsPolicy([/rm\s+-rf\s+\//]),
  approveCommandsPolicy([/git\s+push/]),
];
```


## Updating policies

Call `sandbox.updatePolicy()` to update one tool or every tool. Updates also apply to guards created later.

```ts
// Update every tool.
sandbox.updatePolicy({
  mode: "write",
  default: "ask",
  deny: ["dist/**"],
});

// Update one tool.
sandbox.updatePolicy(
  { mode: "read", allow: ["reports/**"], default: "deny" },
  "read_file",
);
```
