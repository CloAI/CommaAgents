# delete_file

Delete a regular file from the workspace. The original bytes are retained for recovery unless you pass `permanent: true`. Directories are not supported.

```ts
import { createAgent } from "@comma-agents/core";

const agent = createAgent({
  name: "janitor",
  model: "openai/gpt-4o",
  tools: ["delete_file", "restore_file"],
});
```

## Recoverable deletion

Recoverable deletion applies to `delete_file`, existing destinations replaced by `move_file`, and delete operations in `apply_patch`. Ordinary reads, writes, and edits do not create recovery copies.

Read the file first and pass its `sha256` as `expectedSha256` when you need stale-file detection. To restore the deleted file, pass its returned `trashedTo` value as `trashedPath` to `restore_file`.

Files remain recoverable until explicitly restored or cleared. Recovery archives remain under `<dataDir>/trash/<sha256(workspaceRoot)>/`, normally inside `~/.comma`. Each new archive has a timestamp, unique identifier, and original basename. Previously created archives remain readable. Session, run, and agent identifiers are retained as metadata.

Restoration checks the archive's workspace ownership and content hash, refuses an existing destination, and rejects paths that escape the workspace. The archive is removed only after its file has been successfully restored. New archives retain original file permissions; older archives without permission metadata restore with owner-only access.

## Use deletion directly

The same recovery API is available to projects using core:

```ts
import {
  deleteFile,
  restoreDeletedFile,
  listDeletedFiles,
  clearDeletedFiles,
} from "@comma-agents/core";

const workspaceRoot = "/workspace";
const { archivePath } = await deleteFile(workspaceRoot, "src/old.ts", {
  metadata: { runId: "run-1", agentName: "janitor" },
});

const deleted = await listDeletedFiles(workspaceRoot);
if (archivePath) {
  await restoreDeletedFile(workspaceRoot, archivePath, {
    targetPath: "src/recovered.ts",
  });
}

await deleteFile(workspaceRoot, "temporary.log", { permanent: true });
const cleared = await clearDeletedFiles(workspaceRoot);
console.log(deleted.length, cleared.cleared);
```

`clearDeletedFiles` permanently removes the workspace's recovery directory. There is no automatic cleanup. The standalone trash functions have been replaced by these deletion APIs; tool result fields and legacy daemon message names retain their existing names.

## Errors

| Kind                | When                                                           |
| ------------------- | -------------------------------------------------------------- |
| `not_found`         | The path does not exist or is a directory.                     |
| `stale_file`        | The supplied content hash differs from the current file.       |
| `permission_denied` | Sandbox policy blocks deletion.                                |
| `outside_workspace` | The path escapes the workspace or absolute paths are disabled. |
| `command_failed`    | The file could not be archived or deleted.                     |
